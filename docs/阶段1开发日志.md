# 阶段 1 开发日志：统一任务基础设施与 LLM Gateway

## 完成内容

### 1. 任务信封与持久化

- Redis Stream 任务统一携带 `task_id`、`idempotency_key`、`deadline`。
- 执行记录持久化到 `async_task_executions`。
- 增加 `workflow_id`、`step_id`、`user_id`、重试时间和死信原因字段。
- 支持重复投递幂等、失败任务重试和超时状态记录。

### 2. 超时、取消与死信

- 统一任务超时策略。
- 支持 Redis 取消标记，Worker 发现取消后跳过业务处理。
- 超过最大投递次数后进入死信队列，并同步数据库状态。
- 状态覆盖 `PENDING`、`PROCESSING`、`RETRYING`、`COMPLETED`、`FAILED`、`TIMEOUT`、`CANCELLED`、`DEAD_LETTER`。

### 3. 任务管理接口

- `GET /api/tasks`：查询当前用户任务。
- `GET /api/tasks/{task_id}`：查询任务详情。
- `POST /api/tasks/{task_id}/cancel`：取消任务。
- `POST /api/tasks/{task_id}/replay`：重放失败、超时或死信任务。
- 接口按 `user_id` 过滤，不能读取其他用户任务。

### 4. LLM 调用追踪

- 统一记录请求 ID、模型、Token 使用量、耗时、超时、限流和异常信息。
- 支持从多种 provider 返回格式提取 usage metadata。
