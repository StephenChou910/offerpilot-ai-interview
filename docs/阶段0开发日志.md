# 阶段 0 开发日志：基线盘点与安全加固

> 阶段状态：核心开发与验收完成
>
> 完成日期：2026-09-29
>
> 项目：OfferPilot AI Interview Platform

## 一、阶段目标

阶段 0 的目标是在不改变主要业务流程的前提下，建立安全、可观测和可验证基础：

- 生产配置能够识别默认凭据和关键密钥缺失；
- API 请求具备可追踪的 request ID；
- 外部工具和实验能力有明确的状态标识；
- 简历、知识库、知识图谱、面试和 Agent 数据具备用户隔离；
- 建立基础回归测试和运行态验证流程。

## 二、实施内容

### 1. 生产配置启动校验

修改 `app/common/config_check.py`，在 `strict_config=true` 时增加：

- PostgreSQL 密码不能使用默认值；
- MinIO/对象存储密钥不能使用默认值；
- `JWT_SECRET_KEY` 必须配置且长度不少于 32 位；
- 原有 AI、Embedding、数据库、Redis 和 CORS 检查继续保留。

严格模式发现错误时，应用启动失败，避免生产环境以开发凭据运行。

### 2. 请求追踪与错误关联

新增 `app/common/request_context.py`，并修改全局认证中间件：

- 透传请求携带的 `X-Request-ID`；
- 未携带时自动生成 request ID；
- 将 request ID 写入 request state 和上下文变量；
- 所有响应返回 `X-Request-ID`；
- 认证失败和全局异常响应包含 `request_id`。

### 3. 能力状态接口

新增公开接口：

```text
GET /api/health/capabilities
```

当前状态包括：

- `resume_ocr`：`PLANNED`
- `knowledge_graph`：`EXPERIMENTAL`
- `agent_orchestration`：`EXPERIMENTAL`
- `github_tools`：`EXPERIMENTAL`
- `arxiv_tools`：`PLACEHOLDER`

接口不暴露密钥或内部连接信息。

### 4. 知识图谱用户隔离

审计发现知识图谱部分查询原先未按用户知识库过滤，存在潜在越权风险。已完成：

- 实体列表、图谱数据、实体详情和三元组查询按用户拥有的知识库过滤；
- 指定 `kb_id` 时校验知识库归属；
- 创建和删除三元组时校验来源知识库归属；
- Agent 知识库构建接口指定已有知识库时校验归属，并传入当前用户上下文。

涉及文件：

- `app/modules/knowledge_graph/persistence_service.py`
- `app/modules/knowledge_graph/router.py`
- `app/modules/agent_orchestration/router.py`

### 5. 测试调整

更新 `tests/test_api_contracts.py`：

- 健康接口服务名改为读取当前配置；
- 增加 `X-Request-ID` 响应头校验；
- 增加能力状态接口测试；
- 增加严格配置拒绝默认凭据的测试。
